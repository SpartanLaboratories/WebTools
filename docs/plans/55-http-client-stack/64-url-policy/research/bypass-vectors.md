# Published bypass vectors for the outbound-URL classifier, and which rule catches each

## Question

Which published bypass vectors must the Level 4a tables of `webtools-http` carry (advisories since 2020 on IP-literal parsing and special-range classification, the SSRF host-form catalogues, URL-parser confusion, the WHATWG IPv4 parser), and does each fall to one of the classifier's rules?

The classifier reads `Url.parse` output. `Url.parse` refuses a non-ASCII, percent-encoded, `xn--`, out-of-charset or mis-sized host, user-info, a backslash, whitespace or control character anywhere, any scheme but `http`/`https`, a bad port, and a malformed or zoned IPv6 literal; it lower-cases, prints IPv6 in RFC 5952 form without brackets, prints an IPv4-mapped literal as dotted IPv4, and keeps digits-and-dots text, hex-looking text and one trailing dot as written. A redirect target is resolved by OkHttp's `HttpUrl` first, and its text then goes through `Url.parse`. For `Untrusted`, the host rules in order: (1) empty, non-ASCII or control is `HostForm`; (2) a host with `:` must parse as strict IPv6, else `HostForm`, then the address table; (3) digits and dots only must be strict dotted-decimal, else `HostForm`, then the address table; (4) a last label (after one trailing dot) of all digits or `0x` plus hex is `HostForm`; (5) single labels, `localhost`, `local`, `internal`, `home.arpa`, `localdomain`, their subdomains and the policy's suffixes are `ReservedName`; (6) any other name goes to the resolver guard. The address table is every IANA IPv4 special-purpose row plus multicast, IPv6 default-deny outside `2000::/3` with the special blocks inside denied, IPv4-mapped and NAT64 `64:ff9b::/96` judged by the embedded IPv4, 6to4 and Teredo wholesale. The default ports are 80, 443, 8080 and 8443.

## Bottom line

- **Every published host-form vector found falls to an existing rule, with two exceptions that pass all of them.** The host and URL strings of the advisories (2020 to 2026), the two catalogues and the Orange Tsai deck are mapped in section 3. Each is refused by `Url.parse` (with a named `UrlProblem`), or is `HostForm`, `ReservedName`, a `DeniedAddress` row, or a name for the resolver guard.
- **Design gap 1: `168.63.129.16` (Azure WireServer) passes every rule.** It is a real public address outside every IANA special-purpose row, answers on port 80 (an allowed port), and is listed in both catalogues' cloud pages. Closing rule: one explicit non-IANA row, `168.63.129.16/32`, in the address table. One mature guard (`intentkit`) carries exactly this single entry for exactly this reason.
- **Design gap 2: an ISATAP address inside `2000::/3` passes every rule.** `[<any global prefix>:0:5efe:7f00:1]` (interface identifier `0000:5efe` or `0200:5efe`, then an IPv4 address) is outside every denied block. A 2026 advisory (openclaw GHSA-8cp7-rp8r-mg77) and a 2026 pydantic-ai advisory name it; reachability needs an ISATAP interface on the host, so it is rare but real. Closing rule: deny, anywhere in `2000::/3`, an address whose bits 64 to 95 are `0000:5efe` or `0200:5efe` (wholesale, or judged by the low 32 bits like NAT64).
- **The IPv6 transition family is the largest 2026 vector class and the table already holds every member** (IPv4-compatible `::a.b.c.d`, SIIT `::ffff:0:a.b.c.d`, NAT64 well-known and local-use, 6to4, Teredo, site-local, multicast), provided the tests feed the parsed-bytes spellings the printer actually emits (`64:ff9b::7f00:1`, not `64:ff9b::127.0.0.1`). Operator-chosen NAT64 prefixes cannot be known to a library; `extraDeniedRanges` is the seam, and the KDoc should say so.
- **Transport-owned vectors are listed apart (section 5).** One is new and catches a real bug class: `HttpUrl.resolve(link)` catches only `IllegalArgumentException`, so a `Location` of `//[1:2:3:4:5:6:7::8]/` throws `ArrayIndexOutOfBoundsException` out of the redirect loop unless the transport catches it.
- **Three small totality changes to `HostRules`** make it safe when called with a string that did not come from `Url.parse` (section 3.7): treat any character outside the name or IPv6 charset as `HostForm`, compare case-insensitively (`0X7F`, `LOCALHOST`), and have the test pin which reason wins when two rules apply (`127.0.0.1:6379` is both `DeniedAddress` and `Port`).

## Findings

Evidence tiers: **consensus** (several independent credible sources or a standard), **common practice** (what mature libraries visibly do), **single source**. All advisory text was read through `gh api advisories/<GHSA>` (GitHub Advisory Database) on 2026-10-25; "published" dates are the database's.

### 1. How the sources were searched

- **GitHub Advisory Database (consensus on the class list).** All reviewed advisories with CWE-918, published since 2020-01-01: 1,052 entries. I filtered titles for address-classification words (IPv4, IPv6, private, loopback, bypass, mapped, octal, 0.0.0.0, NAT64, zone, rebinding and so on), then read the descriptions of the classification advisories. This is a title filter, so it is not exhaustive; advisories without CWE-918 and unreviewed advisories were not scanned.
- **NVD (small supplement).** Keyword queries (`ssrf nat64`, `ssrf octal`, `ssrf isatap`, `ssrf 168.63.129.16`) through `services.nvd.nist.gov/rest/json/cves/2.0`. They added EspoCRM CVE-2026-33534 (octal `0177.0.0.1` fell through to a DNS lookup that returned nothing and the host was treated as safe) and Vaultwarden CVE-2026-47160 (decimal, hex and octal forms), both already covered by the `HostForm` rules; AVideo CVE-2026-82648 (hex-encoded NAT64) is the printer-spelling pitfall in section 4.
- **Catalogues, pinned.** PayloadsAllTheThings `Server Side Request Forgery/README.md` and `SSRF-Cloud-Instances.md` at commit `3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a` (2026-08-27); HackTricks `src/pentesting-web/ssrf-server-side-request-forgery/url-format-bypass.md` and `cloud-ssrf.md` at commit `16689f85469c3a35946b6ad88e1357cb9ec5a776` (2026-10-25).
- **Orange Tsai, Black Hat USA 2017.** The Black Hat PDF and the OWASP-hosted copy have identical extracted text (839 lines each); quotes below come from it.
- **WHATWG URL Standard,** living standard last updated 2026-10-19, source at `whatwg/url` commit `845bafca22fb0c5a42c4bf384a9bdea525a2f10d`.

### 3. The vector table

Notation. **Parent** says whether the vector is already in the parent research `research/outbound-url-policy.md`: `F1` (the 39 host forms measured through OkHttp 5.5.0), `F2` (canonicalisation), `F3` (parser-disagreement table), `F10` (advisories to 2024), or `new`. **Stage 1** is `Url.parse(text)`; **stage 2** is the classifier on the resulting `Url.host`. `UrlProblem` names are the `internal enum` in `UrlProblem.kt`. Where the published string is not a full URL, the test wraps it as `http://<host>/`. Where two rules apply, the test should pin which reason the guard reports (3.7).

### 6. Why the rules hold (reasoning, flagged as mine)

Rule 4 is complete for numeric spellings because every string the WHATWG parser, `inet_aton` or the JDK reads as an IPv4 literal ends in a number: a decimal, octal or `0x` hex last label. The WHATWG checker states the test: "If last is not the empty string and contains only ASCII digits, then return true." and the note "This is equivalent to checking that last is "0X" or "0x", followed by zero or more ASCII hex digits." The `inet_aton` half of that claim is my reasoning from its documented forms and was not measured here. The implementation must let zero hex digits count (`0x` alone, `127.0.0.0x`).

## How comparable projects do it

- **openclaw** `packages/net-policy/src/ip.ts` (commit `4fa442e`): decodes the embedded IPv4 from IPv4-compatible and ISATAP addresses, with `const isIsatap = (parts[4] & 0xfcff) === 0 && parts[5] === 0x5efe;`. The mask `0xfcff` ignores the universal/local and group bits of the interface identifier's first byte.
- **intentkit** `intentkit/utils/ssrf.py` (commit `afc8cc4`): keeps a single non-IANA entry, `ipaddress.ip_address("168.63.129.16"),  # Azure wireserver`, under the comment "Metadata services that sit on a globally routable address, so the is_global test below cannot catch them."
- **private-ip 2.0.0** (commit `840664c`): replaced the regex with a CIDR list of the IANA rows and added a 92-address boundary test; this is the model for the 4a row-boundary test.
- **Hugo** v0.163.1 and **Symfony**: Hugo "canonicalized to dotted-decimal before the policy is applied"; this design instead refuses the lenient forms (`HostForm`), which the parent research argues removes the disagreement class. Symfony's fix added the transition prefixes to its list.
- **CPython 3.13**: `192.0.0.0/24` private except `.9` and `.10`, plus `64:ff9b:1::/48` and `2002::/16`, with `2001::/23` exceptions; this design denies the `/24` and `2001::/23` wholesale, a safe superset of those private ranges.

## Pitfalls & regrets

1. **Judging the printed text of an embedded address.** ssrfcheck's regex matched `::ffff:127.0.0.1` in dotted form, but the WHATWG printer normalises to `[::ffff:7f00:1]` ([GHSA-j4rj-2jr5-m439](https://github.com/advisories/GHSA-j4rj-2jr5-m439)); AVideo CVE-2026-82648 is the same bug for hex NAT64. Classify parsed bytes, and feed the test every spelling.
2. **Incomplete fix chains.** `ip` (two CVEs), `netmask` (two), pydantic-ai (four in six months), AVideo, Mailpit, Budibase: each fixed the reported spelling, not the class. The table and the form rules must be written from the registries and the grammar, with the vector list as a regression net.
3. **A narrow special-purpose list.** Python's pre-fix `192.0.0.0/29` + `192.0.0.170/31` missed Oracle's `192.0.0.192`; deny the whole `/24`.
4. **Treating an unresolvable-looking name as safe** (EspoCRM CVE-2026-33534; Guzzle: "any check that treats an unresolvable name as safe"). `HostForm` refuses the numeric spellings before any lookup.
5. **Set-membership blocklists on IPv6 text** (pydantic-ai zone suffix). Zones are refused at `Url.parse`; classification is by range on bytes.
6. **Prefix length taken from the input** (ip-address `/0`). `Url.host` carries no prefix; `CidrBlock` matching must use the address's full width.
7. **A second parser deciding.** Orange: "It's all about the inconsistency between URL parser and requester"; Spinnaker's `java.net.URL` underscore bug. The classifier reads `Url.host` only.
8. **Reason precedence.** `http://127.0.0.1:6379/` is both `DeniedAddress` and `Port`; an unpinned order makes the test flaky across refactors.

## Recommendation for this repo

Keep the settled rules and add three things.

1. **Add the ISATAP rule to the address table** (G2): in `2000::/3`, bits 64 to 95 equal to `0000:5efe` or `0200:5efe` are denied. It is one mask comparison, it has a 2026 advisory and a mature implementation behind it, and nothing legitimate is lost.
2. **Add one non-IANA row, `168.63.129.16/32`** (G1), commented as a provider service address that the IANA registries do not list. Add a short "cloud endpoint" block to the Level 4a row test (`169.254.169.254`, `169.254.170.2`, `100.100.100.200`, `192.0.0.192`, `fd00:ec2::254`, `168.63.129.16`) so a later narrowing of an IANA row fails visibly. Say in the `extraDeniedRanges` KDoc that a deployment behind NAT64/DNS64 with its own prefix (G3) or with a known internal service on a public address (G4) adds it there.
3. **Make `HostRules` total on its own input:** rule 1 also treats any character outside `a-z 0-9 - _ .` (and, for IPv6, `0-9 a-f :`) as `HostForm`; compare ASCII case-insensitively so `0X7F` and `LOCALHOST` behave; and pin the precedence in the test as scheme, host form, reserved name, address, port.

Build the 4a test as one data table, one row per vector in section 3 with the columns `id, source, text, stage-1 outcome, host, stage-2 outcome`, run through `Url.parse` first and the classifier second, and carry the parent's F1 and F10 rows by id (`Parent` column) so nothing is entered twice. The rows N01 to N06 belong to the resolver-guard test (Level 2), not 4a. The two additions are the reason to reject "the rules as designed, no addition": both vectors are published, both pass, and each costs one table row.

### Considerations

1. **Default deny table gains two rows that the IANA registries do not list.** Options: (a) add G1 and G2 to the default table (recommended: both are published, the false-deny cost is nil, and the table is Stable Core so later additions are behaviour changes anyway); (b) leave both to `extraDeniedRanges` and the KDoc (the default stays purely IANA-derived, but every consumer must know). Recommendation: (a), with the "not an IANA row" note in the source so a refresh does not delete them.
2. **ISATAP: wholesale denial or judge the embedded IPv4.** Wholesale is simpler and removes a branch; judging the embedded address matches openclaw and NAT64. Recommendation: wholesale.

## Gaps

- **Search coverage is a title filter over 1,052 CWE-918 advisories plus four NVD keyword queries.** Advisories without CWE-918, unreviewed advisories, and CVEs outside GitHub's reviewed set were not scanned. NVD's own full-text search was used only for `nat64`, `octal`, `isatap` and `168.63.129.16`.
- **No vector was run.** Every expected outcome comes from reading `UrlParsing.kt`, `UrlHost.kt` and `UrlProblem.kt` and the parent research's measurements, not from executing `Url.parse`. The IPv6 print forms in section 3.3 were derived by hand from `formatIpv6`; the implementation's tests confirm them. Where the parent research measured a form through OkHttp (F1, F2, F3), the `Parent` column says so.
- **The `inet_aton`, glibc and Windows resolver behaviours behind rule 4's completeness** (section 6) are my reasoning from documented forms, not a measurement.
- **Reason precedence is not fixed by the settled rules** (3.7, pitfall 8). The test needs the order; this report recommends scheme, host form, reserved name, address, port, but the design owns it.
- **G1 and G2 are additions to a Stable Core default table.** They are recommendations in Considerations, not settled rules. No other non-IANA provider address was found in the two catalogues' cloud pages; I did not search the providers' own documentation for further virtual public addresses.
- **G3 and G4 cannot be closed by a table.** They are documentation and `extraDeniedRanges` matters.
- **Orange Tsai's deck was read as extracted text.** The slide images (parser comparison tables per language) carry detail the text does not.
- **The `HttpUrl` mapping of the non-ASCII rows (P14) onto `Url.parse` input after a redirect** was measured for the fullwidth, circled and full-stop forms in the parent research (F2); the zero-width joiner and `ß` forms were not run through `HttpUrl`, only through `Url.parse` by reading.
