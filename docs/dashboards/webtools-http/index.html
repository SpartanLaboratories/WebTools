webtools-http

A suspend HTTP stack for Kotlin, built in part: the request and response types, a canonical Url that parses like OkHttp's HttpUrl and is only ever stricter, a typed failure model returned inside Result, and the transport and wall-clock ports a consumer calls or, with the opt-in, implements; the outbound-URL policies Trusted and Untrusted with their TransportSettings, judged by an internal, JVM-free address classifier and by internal resolver and socket guards; OkHttpTransport, which enforces a policy on every hop: one request per hop and never a retry, manual redirects, one deadline, a capped decoded body, every outcome a Result; the ResponseCache port with CaffeineResponseCache, its supplied default: one load per key at a time, per-entry lifetimes, a weight bound, a per-call maxAge, failures never stored, and the pass-through ResponseCache.Disabled; and a published test-fixtures variant, so a consumer tests its providers with a scripted fake, one virtual clock, .http fixtures and a gated, redacting recorder, or with the real transport over loopback. The budget and the call facades are the stack's later units, drawn dashed.

Lifecycles and rules

    
A transport's and a cache's life, how values and policies are built, and the rules the module holds to.

    

      
A transport's life HttpTransport's contract

        
  1. constructed by its implementation: OkHttpTransport(userAgent, policy), the fixtures' FakeHttpTransport and the recorder's decorator
  2. execute(request): one request per hop, never a retry; concurrent calls allowed
  3. a status in 100..599 is a response, a 304 included; outside it, Protocol
  4. close(): idempotent, non-suspending, never throws
  5. after it, execute returns HttpFailure.Closed("transport")

        
Cancellation is thrown, never wrapped in a Result.

      
Building a value the factories

        
  1. HttpHeaders { add(name, value) }: names are RFC 9110 tokens, values hold no CR, LF or NUL
  2. HttpRequest(method, url) { … } refuses, in order: CONNECT, an unsendable value, a body on GET, HEAD or TRACE, a second content type
  3. HttpResponse(status, url) { … } takes 100..599; RedirectHop 300..399

        
A developer-written value throws IllegalArgumentException at construction; text from outside the process returns Result.

      
Rules the module holds to

        
Values are immutable. Byte arrays are copied in and read back as copies, so a response shared by several callers cannot be changed by one. Url, HttpMethod, HttpHeaders, RedirectHop and the reasons compare by value; HttpRequest, HttpResponse and RequestBody by identity.

        
Nothing prints a secret. toString() shows names, the method or status, the redacted URL, sizes and a Found's weight, never a header value, a body or a cached value; a CacheKey prints its parameter names only; a failure's message is constant text plus named non-sensitive fields.

        
Common code stays common. webtools-http-commoncheck compiles commonMain for js in check, so a JVM API there is a compile error; the URL policy's classifier is common code under the same check.

        
One DSL scope per block. @WebToolsDsl marks the eight builders a consumer's lambda receives, so inside a nested block an outer builder is reached only through its label (this@untrusted.allowedPorts).

      
Building a policy configuration values

        
  1. OutboundUrlPolicy.untrusted { } starts from ports 80, 443, 8080 and 8443, MixedAnswers.Reject and TransportSettings.UntrustedDefaults; trusted { } from no pins, no cleartext and TrustedDefaults
  2. settings { } inside the block derives new settings from the policy's current ones
  3. the block's end validates every value and throws IllegalArgumentException: an empty port set or a port outside 1..65535, a pinned host or a suffix that is not a host, a timeout outside 1 ms to Int.MAX_VALUE ms, a cap or a concurrency below 1, a negative redirect limit
  4. untrusted(from) { } and trusted(from) { } derive a new policy; policies and settings compare by value

        
No parameter lets a denied address, a reserved name or a malformed host through: extraDeniedRanges and extraDeniedHostSuffixes only add denials, and the one relaxation, loopback for tests, is internal and reached only through the fixtures. OkHttpTransport applies a policy to every hop.

      
One call through the guards internal · applied by the OkHttp transport

        
  1. the guard judges the URL before any call: an IP-literal host is judged here and never reaches the resolver
  2. GuardedDns.lookup judges every resolver answer: Reject refuses it whole, DropDenied keeps the allowed addresses in order
  3. GuardedSocket.connect, a Socket(Proxy.NO_PROXY) that ignores a JVM-wide SOCKS setting, judges every target before any I/O
  4. a refusal ends the call as PolicyRefusedUnknownHost or PolicyRefusedIo, constant messages with no stack trace, which policyRefusal() finds through the causes and the suppressed lists; the transport returns it as RefusedByPolicy, with one WARN line

        
Measured through a real OkHttpClient and the real transport in the module's Level 3 tests on JDK 23.0.2 and Windows 11, on loopback.

      
An OkHttpTransport's life one client per transport

        
  1. OkHttpTransport(userAgent, policy) validates both, then builds one client with its own dispatcher and connection pool; it throws IllegalArgumentException, leaving no thread behind, for a blank or non-printable userAgent or a maxResponseBytes above 2,147,483,639
  2. execute(request): the controlled headers, then the policy, both before any socket; then one Call per hop under one deadline
  3. a hop's response decides: Protocol outside 100..599, a followed redirect with no body read, else the response with its capped body
  4. close(): cancels every call in flight, each ending Closed("transport"); shuts the dispatcher down; evicts the idle connections
  5. after it, execute returns Closed("transport"); a second close() does nothing

        
Never a retry: OkHttp's retries, redirects, authentication, cookies and cache are off, and a network interceptor fails a second exchange of one hop as RetryRefused; a 407, 408, 421 or 503 is delivered once, as the response it is.

      
A CaffeineResponseCache's life the supplied cache

        
  1. CaffeineResponseCache { maxWeight = 5_000 }: every property has a default (timeSource, maxWeight 1,000, loadDispatcher, maintenanceExecutor); it throws IllegalArgumentException for a maxWeight below 1
  2. getOrLoad(key, policy, maxAge, loader): a live entry within maxAge is served; a call while a load is in flight joins it; otherwise the call starts one, in the cache's own scope
  3. a load's end: a Found stored for ttl, a Missing for missTtl, each from the load's completion; a zero TTL or a value over maxWeight is delivered and not stored; a failure is never stored
  4. close(): idempotent, non-suspending, never throws; cancels the loads in flight, ends every waiting call with Closed("cache") without waiting for a loader to unwind, and drops every stored entry
  5. after it, getOrLoad returns Closed("cache") without running its loader; invalidate and invalidateAll are no-ops, stats keeps working

        
Three execution contexts: a caller only awaits, and its cancellation cancels only that caller; a loader runs in the cache's scope on loadDispatcher; Caffeine's maintenance runs on maintenanceExecutor. A loader must not wait for a load of its own key.

      
A loopback test the real transport, no outside network

        
  1. MockWebServer started on 127.0.0.1; LoopbackTransports.untrusted(userAgent, policy, resolve) or trusted(…) builds the real transport
  2. server.enqueue(fixture, method) serves the same .http file the fake replays, written by toMockResponse
  3. execute(HttpRequest(HttpMethod.Get, server.webtoolsUrl("/x"))): every rule of the policy stays live but the loopback host, addresses and their port rule
  4. the test closes the transport and the server

        
Not a production switch: the relaxation is reached only from the fixtures, on a consumer's test classpath; nothing here is reachable from the main artifact.

      
A test with the fixtures no network

        
  1. runTest { val clock = virtualClock() }: one scheduler drives the time source, the wall clock, the dispatcher and the executor
  2. FakeHttpTransport(clock.timeSource).on(match, steps…): the latest stub that matches wins; its steps run in order and the last repeats
  3. execute(request): recorded with a virtual stamp, then the step's delay; an unmatched request throws UnmatchedRequestError
  4. clock.advanceBy(d): moves every clock at once and runs what fell due
  5. close(): idempotent; every later call returns Closed("transport")

        
Never at Level 3: real I/O under runTest turns withTimeout into a spurious timeout, as the clock's KDoc says.

      
Recording a fixture behind the gate

        
  1. RecordingGate.evaluate(): off unless WEBTOOLS_HTTP_RECORD allows it; refused when any of twelve CI variables is set
  2. FixtureRecorder(directory, gate) takes only RecordingGate.Enabled
  3. wrap(live, group): each successful response is redacted, scrubbed of the supplied secrets and written; no request header is written
  4. a file in which a secret's form survives is refused, listed in refused, never written
  5. the wrapper's close() closes the live transport

        
Replay: Step.fixture(FixtureLoader().load("group/name.http")) reads it back from the consumer's own classpath; a consumer marks **/fixtures/**/*.http -text in its .gitattributes.

Guarantees

  

    
Failure model

      
  • Url.parse and HttpMethod.of return Result.failure(IllegalArgumentException) with a constant message that never echoes the input.
  • A port returns its HttpFailure inside the Result: a TransportFailure leaf, an UpstreamFailure, or Closed after close().
  • Thrown, not returned: IllegalArgumentException from a factory given a broken developer-written value; cancellation.
  • Retried inside: nothing; a transport sends one request per hop.
  • OkHttpTransport: a request carrying one of twelve controlled headers fails with InvalidRequest before anything is sent, though HttpRequest builds it. Every other failure is one leaf, first match wins: a policy marker (RefusedByPolicy), a second exchange (RetryRefused), Closed, then DnsFailed, Timeout, TlsFailed, ConnectFailed, Protocol, Io, with BodyTooLarge and TooManyRedirects for its caps. A cause is kept only where its text holds no address. The factory throws IllegalArgumentException.
  • Fixtures: the fake returns its scripted Result, BodyTooLarge over its cap and Closed after close(), and throws UnmatchedRequestError, an Error, for a request no stub matches; FixtureLoader.load throws FixtureError naming the resource and line, never a value; the recorder never fails a call: an I/O failure or a surviving secret lands in refused.
  • URL policy: a broken policy or settings value throws IllegalArgumentException with a constant message when its block ends; CidrBlock.parse returns Result.failure with one of four constant messages. The internal guards refuse with a RefusalReason, and for a denied address its range class, inside markers with constant messages; OkHttpTransport returns them as RefusedByPolicy.
  • Response cache: getOrLoad returns a loader's failure inside the Result, the same instance for every waiter, and never stores it, so the next call loads anew; Closed("cache") after close(). A loader's Error is rethrown to every waiter as the same instance; a loader's own cancellation becomes Result.failure(IllegalStateException(…, cause)); a negative maxAge throws IllegalArgumentException; a caller's own cancellation is thrown and cancels only that caller.

    
Extension points

      
  • HttpTransport, WallClock, ResponseCache — implement Experimental behind @OptIn(ExperimentalForInheritanceWebToolsApi::class); calling and passing them are Stable Core
  • HttpFailure, TransportFailure, UpstreamFailure — subclass Experimental, the same marker
  • RefusalReason, ExhaustedReason — may gain constants; keep an else Stable Core
  • OutboundUrlPolicy (sealed, its Trusted and Untrusted final), TransportSettings, CidrBlock — final values built by factories over internal constructors; MixedAnswers is an enum a consumer chooses; WebToolsDsl marks every builder. The address classifier and the guards are internal: no seam for a consumer's own guard Stable Core
  • OkHttpTransport — final, built by the factory OkHttpTransport(userAgent, policy), usable without the opt-in; every number comes from the policy's settings, with no builder and nothing to override Stable Core
  • CaffeineResponseCache — final, built by its factory, usable without the opt-in; its builder sets timeSource, maxWeight, loadDispatcher and maintenanceExecutor. ResponseCache.Disabled needs no opt-in either; Lookup is sealed, its closed pair the contract, so a when over it needs no else Stable Core
  • Every other public type is final or a factory Stable Core
  • Test fixtures — every class final, RecordingGate and Unmatched sealed; source compatibility only, since no ABI dump covers them. FakeHttpTransport and the recorder's decorator are the worked examples of implementing HttpTransport with the opt-in, VirtualClock's wall clock of WallClock. LoopbackTransports, webtoolsUrl, toMockResponse and enqueue(fixture) are the way to the real transport over loopback Stable Core

Compatibility & versioning

      
  • Version 1.0.0, from the root default: new, unreleased, not on Maven Central until the HTTP stack is complete.
  • Checked: the ABI dump api/webtools-http.api (557 lines, the response cache the last addition) by apiCheck, and the Java 11 floor by verifyJavaFloor, both in check. The dump does not record @SubclassOptInRequired or sealed, and no permanent check proves the gate or the effect of WebToolsDsl; a Level 1 test's when with no else holds Lookup's sealed.
  • WebToolsDsl on the request, response and header builders tightens a consumer's source: a lambda that reaches an outer builder implicitly stops compiling. Nothing is released, so no published consumer has one.
  • The test-fixtures variant rides in the same 1.0.0 (capability webtools-http-test-fixtures), released and versioned with the module. No dump covers it; fixturesPublicationCheck, in check, asserts its two variants, their dependencies, a signature beside every published file and its resolution from three build shapes.
  • Experimental seams may change in a minor release; Stable Core changes only in a major. ResponseCache's implementation seam graduates to @SupportedExtension once a consumer has built against it, recorded in CHANGELOG.md.

    
Thread safety

      
  • Safe to share: every value type, which is immutable, WallClock.System, which is stateless, and OkHttpTransport, whose only mutable state is its closed flag.
  • HttpTransport.execute may be called concurrently and is main-safe: OkHttpTransport does every blocking step on its own daemon dispatcher threads, never on the caller's thread or dispatcher. A WallClock implementation must be safe for concurrent calls.
  • Confined: a builder, reachable only inside its factory's lambda.
  • URL policy: policies, settings and CidrBlock are immutable values, safe to share. The internal guards hold no state beyond their references, are safe to share between calls and clients, and run on whichever thread OkHttp resolves or connects on.
  • Fixtures: FakeHttpTransport and FixtureRecorder are safe to share, each behind one lock never held across a suspension, their lists snapshots; FixtureLoader is stateless; VirtualClock's readings are safe from any thread, advanceBy from the test's thread only.
  • Response cache: every member of a ResponseCache may be called concurrently from any thread and any number of coroutines; CacheKey, CachePolicy, Lookup and CacheStats are immutable, Disabled stateless and shared; stats() reads its four counts separately, not atomically.

    
Resources to close

      
  • HttpTransport is AutoCloseable: close() is idempotent and never throws; the default does nothing.
  • OkHttpTransport.close() cancels every call in flight, shuts its dispatcher down and evicts its idle connections, and is the supported stop. Skipped, nothing keeps the JVM alive: its threads are daemons, gone after 60 s idle, and a pooled connection goes after idleConnectionTtl.
  • Fixtures: FakeHttpTransport.close() is idempotent, and every later call returns Closed; the recorder's wrapper closes its delegate. FixtureRecorder holds no open file: each write goes to a temporary file moved into place.
  • ResponseCache is AutoCloseable: close() is idempotent, non-suspending and never throws. CaffeineResponseCache.close() cancels the loads in flight, ends every waiting call with Closed("cache") and drops every stored entry. Skipped, nothing of its own keeps the JVM alive: it owns no thread, timer or pool, and it never shuts down the maintenanceExecutor it was given. ResponseCache.Disabled.close() does nothing.
  • No other type holds a resource, a policy included.
