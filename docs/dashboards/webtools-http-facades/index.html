webtools-http-facades

The call facades of the suspend HTTP stack: they compose the outbound-URL policy, the response cache, the call budget and the transport in one fixed order and own what they built. UpstreamClient calls the endpoints of one upstream API from a base URL: a consumer declares each Endpoint once, with its decoder, lifetimes, cost, lane and miss statuses, and calls it with call(endpoint) { }. The call is checked and pre-checked against the policy before anything is spent, a GET is served from the cache, and only a load takes a budget permit and sends one request, so a hit costs nothing and many callers of one key share one permit. The answer comes back as Found, Missing or a typed failure, a throttle as RateLimited, never retried. UrlFetcher is the front door for URLs an administrator supplies: the pre-check, the budget and the transport, and every status but a throttle returned as the response. On the JVM the owning factories build the transport, a Caffeine cache and a windowed budget, size the transport to the budget's burst and close them in the order cache, budget, transport; LoopbackFetchers runs a fetcher over a loopback server in a consumer's tests.

Lifecycles and rules

    
A client's, a fetcher's and an endpoint's life, the order of one call, and the rules both facades hold to.

    

      
An UpstreamClient's life the owning factory on the JVM

        
  1. the configuration is checked in order: defaultMaxWait not negative, a base URL with no query that the policy allows, no default header the transport controls, and under Untrusted none sensitive; a refusal throws IllegalArgumentException with a constant message
  2. the owning factory builds the budget from budget(windows), then an OkHttpTransport sized to its maxBurst, then a CaffeineResponseCache unless one was passed; a refused step closes what was built first; one INFO line
  3. call from any number of coroutines; utilisation(), cacheStats()
  4. flush() for a persistent budget's exact final write, then close(): the cache, the budget and the transport it built, in that order
  5. after close() a call returns Closed("client"); utilisation, cacheStats and flush keep working

        
Never what it was handed: a cache, a budget or a transport the consumer passed in stays the consumer's to close.

      
A UrlFetcher's life administrator-supplied URLs

        
  1. UrlFetcher(userAgent) { }: the Untrusted defaults; UrlFetcher(userAgent, policy) { }: a policy of the caller's own; the configuration's check runs first, so a refusal builds no transport
  2. fetch(request) { }: the response for every status but a throttle, a 304 and a returned 3xx included
  3. close() closes the transport only when an owning factory or LoopbackFetchers built it, never the budget
  4. a fetch after close() returns Closed("fetcher")

        
No endpoint, no decode, no cache: an administrator's URLs are an unbounded key space, and a conditional GET is their cache.

      
One call, in order UpstreamClient.call

        
  1. closed? then the settings, maxWait and maxAge, the URL, the controlled headers and the request: each refusal an InvalidRequest, logged once at DEBUG
  2. the policy's pre-check: a refusal is RefusedByPolicy, logged once at WARN
  3. a GET through the cache, keyed by the endpoint id, the request path and the query pairs; any other method straight to the loader
  4. the loader: one permit, one request, the rate signals read, the permit completed
  5. a throttle, then a declared miss, then a 2xx decoded, else UpstreamError; one DEBUG line per call

        
A shared load runs the first caller's request, with its lane and wait cap: per-call headers must not change the answer of a cached endpoint.

      
An Endpoint's life declared once, reused

        
  1. Endpoint(id, decode) { ttl; missTtl; cost; lane; misses(…) }: the decoder is the second argument, the lambda the configuration
  2. checked at construction: a blank id or name, a negative duration, a cost below 1, or a miss status outside 100..599 or 429 throws IllegalArgumentException naming the property
  3. defaults: ttl zero (loads in flight still coalesce, nothing is stored), missTtl the smaller of ttl and 60 s, cost 1, Lane.Interactive
  4. immutable; equality is identity; its toString() never prints the decoder

        
One id, one value type: two endpoints sharing a cache must not share an id.

      
Rules both facades hold to

        
Nothing the facade refuses costs anything. A closed facade, an InvalidRequest it raises and the pre-check's refusal take no permit and send nothing; a cache hit and a joined load spend nothing.

        
A granted permit stays spent. A response of any status spends it, only the transport's InvalidRequest gives it back, and every other failure, a cancellation and an Error leave it spent, so a window that guards a bill is never under-counted.

        
Never a retry. A throttle pauses a windowed budget and returns RateLimited, its retryAfter the longer of the server's Retry-After and the budget's pause.

        
Nothing prints a header value, a body or a query string, nor a decoded value; a URL is printed through Url.redacted(), path shown and query hidden.

Guarantees

  

    
Failure model

      
  • call returns Result<Lookup<T>>: Found, Missing (a declared miss status), or a failure, never stored: Closed("client"), InvalidRequest, RefusedByPolicy, BudgetExhausted, the transport's and the cache's failures, RateLimited, UpstreamError with the status, headers and body, or DecodeFailure; a decoder's own HttpFailure passes through.
  • fetch returns the HttpResponse for every status but a throttle, or one of the same failures, Closed("fetcher") after close().
  • Thrown, not returned: IllegalArgumentException from a factory, with a constant message; the caller's CancellationException; an Error. Retried inside: nothing.
  • A cancellation that is not the caller's, thrown inside a part the consumer supplies, reaches call as an IllegalStateException (the cache's loader rule) and is thrown out of fetch; a budget that throws, against its port's contract, makes fetch throw.

    
Extension points

      
  • No seam of its own: every type is final and Stable Core, usable without the opt-in Stable Core
  • The common factories take any HttpTransport; cache(…) and budget(…) take any ResponseCache or CallBudget, and rateSignals any RateSignalsReader: implementing those ports is Experimental behind @OptIn(ExperimentalForInheritanceWebToolsApi::class), on their own boards
  • The builders carry @WebToolsDsl, so an outer receiver's member is out of reach inside a lambda Stable Core
  • LoopbackFetchers is Stable Core with source compatibility only

Thread safety

      
  • Every member of UpstreamClient and UrlFetcher may be called concurrently from any thread and coroutine.
  • The closed flag is a completed Job: one caller wins close(), and the closing step runs once.
  • Endpoint is immutable, its misses a read-only copy; the factories are safe from any thread.
  • Confined: CallSpec, FetchSpec, the two configurations and Endpoint.Builder, each reachable only inside its lambda.

    
Resources to close

      
  • Both facades are AutoCloseable: close() is idempotent, non-suspending, never throws and safe from any thread.
  • The client closes what it built, cache, budget, transport, each step's failure logged and the next still closed; the fetcher its transport when it was built for it; neither closes what it was handed.
  • Skipped: an owned transport's daemon threads end after 60 s idle and keep nothing alive; an owned budget's waiting calls stay waiting. Call flush() before close() for a persistent budget's exact final write.
  • A part's close() that throws a CancellationException ends the closing order there; no part the facades build throws one.

    
On your classpath

      
  • Nothing of its own: the facades are part of io.github.spartanlaboratories:webtools-http and added no dependency.
  • org.jetbrains.kotlinx:kotlinx-coroutines-core:1.10.2 — api, already the module's; the owning factories reach okhttp-jvm 5.5.0 and caffeine 3.3.1 at runtime, as the transport and the cache do.
  • Test classpath only, through testFixtures(…): LoopbackFetchers, over mockwebserver3 5.5.0. Gradle only.
  • Who consumes it: other repositories of this organization only (visibility internal · org).

    
Logging and secrets

      
  • Two loggers, …http.UpstreamClient and …http.UrlFetcher: INFO on creation and close, one DEBUG line per call or fetch that passed the pre-check, WARN for a pre-check refusal and a throttle.
  • Never a header value, a body, a query string or a decoded value, so never a credential sent in a header or a query pair; credentials added with addSensitive are never printed, and an Untrusted client refuses them as default headers.
  • A URL is printed with Url.redacted(), which shows the path: a secret carried in a path segment, the base URL's path or an administrator's URL is logged, and the client prints an endpoint id as given.

    
Composition limits

      
  • The cache key holds the endpoint id, the request path and the query pairs, never a host: clients sharing one cache need distinct endpoint ids.
  • A shared load carries the first caller's lane and wait cap; a caller with a tighter deadline wraps its own call in withTimeoutOrNull.
  • A refusal the transport makes once the permit is granted, or Closed from a transport the consumer closed, costs one permit. The owning client raises both transport limits to the budget's burst with no ceiling. A default header that is valid but not sendable passes construction and fails every call.
