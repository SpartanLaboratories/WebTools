webtools-udp

A multi-connection UDP transport for the JVM: many clients handshake onto one server port, then exchange framed datagrams over unreliable and reliable-ordered channels, with opt-in keepalive, link-quality probing and idle detection.

Lifecycles and concurrency

    
Ordered shutdowns, the connection states, when a reliable engine comes and goes, and the locking rules.

    

      
Server stop() every step runs even if an earlier one fails

        
  1. stopNotifying
  2. terminateAll
  3. listener join ≤ 1 s
  4. close socket
  5. liveness
  6. keepalive
  7. probe
  8. retransmit
  9. dispatch

        
No onClientDisconnect fires on stop. The 1 s join before the socket closes is an open issue, listed in the Context section.

      
Client stop() each step is its own runCatching

        
  1. stopped = true
  2. listening = false
  3. join
  4. keepalive
  5. probe
  6. retransmit
  7. engine.close()
  8. close socket
  9. dispatch

        
No goodbye on the wire. Neither terminate() nor either side's stop() sends the peer anything; wire protocol 2 has no disconnect datagram. A peer learns the other side has gone only through its own idle detection.

Concurrency rules

        
Lock order is engine → buffer, never reversed. ReliableChannelEngine is @Synchronized; three threads contend per connection — the app thread (send), the listener (inbound), the retransmit tick. The 32-per-tick cap bounds how long the tick holds the lock.

        
One dispatch executor per side serialises unreliable and reliable delivery, so head-of-line blocking on the reliable plane also delays unreliable delivery to that connection.

        
reliableEngineFor, reliableEngine() and ensureListening() are @Synchronized; ensureListening() is idempotent.

Failure model

      
    
        
  • Fallible calls return kotlin.Result. Typed failures: HandshakeRefusedException, IncompatibleProtocolException from handshake(); ReliableWindowFullException, ReliableMessageTooLargeException from a reliable send.
    • 
        
  • Thrown only at construction: SocketException when its port cannot be bound, IllegalArgumentException for a bad parameter.
    • 
        
  • Retried inside: a reliable message, until acked. Not retried: an unreliable datagram; handshake() (4 s timeout — the caller retries).
    • 
        
  • Only logged: a dropped datagram; a throwing admit (the client times out). A throwing onClientConnect kills mcups-listener, an open issue.
    • 
      

    
Extension points

      
    
        
  • MultiConnectionUDPServer, abstract: onClientConnect, admit, onClientDisconnect; constructor knobs for the receive buffer, idle timeout and reliable cap.
    • 
        
  • Connection, UdpChannel: interfaces; of the Connections, only UDPConnection carries a reliable channel.
    • 
        
  • Open sets that may grow without a major: ReliableSendFailure subtypes; DeliveryMode, DatagramType, DisconnectReason entries — keep an else.
    • 
        
  • All Stable Core; the module has no @SupportedExtension or @RequiresOptIn marker.

Compatibility & versioning

      
    
        
  • 2.0.0a in the build, unpublished (Central's latest is 2.0.0), wire protocol 2: a 1.x peer fails handshake() with IncompatibleProtocolException.
    • 
        
  • A trailing letter for a bug fix (2.0.0 → 2.0.0a), the third number for an addition, the major for a break.
    • 
        
  • Deprecate, don't break: the eight members deprecated in 2.0.0 (with ReplaceWith) work through 2.x and go at 3.0.0.
    • 
        
  • Java 11 floor: 2.0.0a is Java 11 bytecode (major 55) compiled against the Java 11 API and declares org.gradle.jvm.version 11, guarded by verifyJavaFloor in check. Central's 2.0.0 is Java 23 bytecode, and 2.0.0a orders below it, so a consumer requests 2.0.0a strictly once it is published.
    • 
        
  • Not checked: the build keeps no ABI dump.
    • 
      

    
Thread safety

      
    
        
  • Any thread: the server's sends (one socket, copy-on-write registry); the client's send, keepalive and probe start/stop, and its idempotent stop().
    • 
        
  • Shareable values: UdpChannel (stateless), LinkQuality (immutable).
    • 
        
  • Never raced: the client's handshake() — once, before start — and start itself (documented, not enforced).
    • 
        
  • Callbacks: admit and onClientConnect on mcups-listener; handlers and onClientDisconnect on the side's one dispatch thread. Racing the server's start* and stop(): not documented.
    • 
      

    
Resources to close

      
    
        
  • MultiConnectionUDPServer.stop(): frees port 9998 and the mcups-* threads; single-use. Skipped, the port stays bound and the next server in that JVM fails to bind.
    • 
        
  • MultiConnectionUDPClient.stop(): frees its port and mcupc-* threads; idempotent. Neither endpoint is AutoCloseable; UDPSendReceiveServer is, and its close() only logs a failure (shutDown() returns it).
    • 
        
  • Connection.terminate(): a timed-out peer stays registered until terminated (TIMEOUT only notifies); it drops the peer's in-flight reliable messages, keepalive and probe.
    • 
        
  • All threads are daemons; nothing goes on the wire at close.
    •
