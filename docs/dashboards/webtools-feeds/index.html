webtools-feeds

RSS 0.90 to 2.0, RSS 1.0 and Atom 0.3 and 1.0 behind a hardened parser port, and a stateless conditional GET to fetch them. FeedFetcher sends a GET through UrlFetcher with Accept and the validators the caller stored, exactly as held; a 200 or 203 is parsed into Fetched, a 304 to a conditional request is NotModified, and both carry the validators to store next, the final URL and any permanent move. The caller keeps every piece of state: the validators, the subscription URL, polling and which entries are new. A parse takes one of the fetcher's parse permits and runs on its parseDispatcher, and cannot be cancelled. RomeFeedParser, the supplied parser, refuses a DOCTYPE and any prolog it cannot read the way the parser reads it before any parser runs, then reads the document with Rome over a SAX parser of its own, bounding depth, attributes, elements and namespace URIs in the same pass, and builds a model whose entry ids are never blank and never change.

Lifecycles and rules

    
A fetcher's life, the order of one fetch and of one parse, the caller's polling cycle, and the rules the module holds to.

    

      
A FeedFetcher's life the owning factory on the JVM

        
  1. the configuration is checked first: maxConcurrentParses at least 1, an accept that is a sendable, non-blank header value; a refusal throws IllegalArgumentException with a constant message and builds nothing
  2. FeedFetcher.untrusted(userAgent) { } builds and owns UrlFetcher(userAgent, OutboundUrlPolicy.untrusted()), or the caller's own Untrusted policy; the common factory takes a UrlFetcher the caller owns; one INFO line names the parser's and the dispatcher's kinds, the concurrency and what it owns
  3. fetch from any number of coroutines
  4. close(): one caller wins the closed flag, the owned UrlFetcher is closed (a failure logged at DEBUG), one INFO line
  5. a fetch that starts after close() returns Closed("feed fetcher"); one already past the check may meet the UrlFetcher's Closed("fetcher") or the transport's Closed("transport")

        
Never what it was handed: a UrlFetcher the caller built stays the caller's to close.

      
One fetch, in order FeedFetcher.fetch

        
  1. closed? then a GET with Accept, and If-None-Match and If-Modified-Since exactly as held
  2. UrlFetcher.fetch with the caller's per-fetch block: the policy's pre-check, one budget permit, one request; any failure returned unchanged, the same instance
  3. the status: 200 or 203 parsed; a 304 to a conditional request NotModified; anything else UpstreamError
  4. a parse permit, then the parse on parseDispatcher; a throw, or a failure that is not an HttpFailure, becomes DecodeFailure
  5. one DEBUG line with the origin, the outcome, the status, the bytes, the entries and the times; a WARN for a refused document

        
A header counts once: a validator appears in the result only when exactly one line of its name is present.

      
One parse, in order RomeFeedParser.parse

        
  1. the prolog scan, before any parser: byte-order marks skipped, three readings within 64 KiB each, the worst outcome kept
  2. Rome's XmlReader, opened the way the scan reads the prolog
  3. a SAX parser of its own: DOCTYPE and external entities off, the depth and attribute limits set, a handler counting elements and distinct namespace URIs
  4. the entries counted before any is converted: more than maxEntries is LimitExceeded(Entries)
  5. the conversion: the id, link and text rules, categories and enclosures cut to their limits, every value built through its factory

        
Two locks on a DOCTYPE: the scan refuses it, and the SAX parser's own ban would refuse it again.

      
The caller's polling cycle what the fetcher keeps: nothing

        
  1. the first poll sends FeedValidators.None, an unconditional request
  2. after every response, store validators first; drop them when finalUrl changes, as a validator from one server must not reach another
  3. adopt permanentlyMovedTo only when the chain's first request was https, or after the same value on several polls
  4. new entries are those whose id has not been seen, never decided by date

        
A permanent move is a fact, not an instruction: it is the target of the leading run of 301 and 308 hops, so a 302 at the head moves nothing.

      
Rules the module holds to

        
A parse cannot be cancelled. It holds its permit until it returns; a cancelled caller sees its cancellation when the parse returns, and a caller cancelled while it waits for a permit starts no parse.

        
Validators are sent verbatim. A date is never reprinted and a tag never normalised; a value that breaks a rule becomes null, never truncated.

        
A URL is printed as its origin: scheme, host and port, never the path or the query; no header value, body or document content is printed.

        
An entry's id never changes: the guid or Atom id, else the link as written, else a digest prefixed webtools-feeds:v1:; a new algorithm would carry a new prefix.

Guarantees

  

    
Failure model

      
  • fetch returns Result<FeedFetch>: Fetched or NotModified, or a failure: every failure of the UrlFetcher unchanged (RefusedByPolicy, RateLimited, BudgetExhausted, the transport's), UpstreamError for any status that is not a feed, a FeedFailure leaf, DecodeFailure for a parser that throws, Closed("feed fetcher") after close().
  • parse returns Result<Feed> and never throws for a bad document: NotAFeed, Malformed, Refused or LimitExceeded, each a constant message with no cause.
  • Thrown, not returned: IllegalArgumentException from a factory or a builder, with a constant message; the caller's CancellationException; an Error. Retried inside: nothing.
  • A fetch racing close() may return Closed under the UrlFetcher's or the transport's component name; match HttpFailure.Closed.

    
Extension points

      
  • FeedParser — a parser of your own, passed as parser in the factory's lambda; implementing it needs @OptIn(ExperimentalForInheritanceWebToolsApi::class) Experimental
  • FeedFailure — subclassing needs the same opt-in Experimental; its four leaves have public constructors, so a parser of your own creates them Stable Core
  • parseDispatcher, maxConcurrentParses, accept and FeedLimits are settings, not seams; RomeFeedParser is final Stable Core
  • NotAFeedReason, FeedRefusal and FeedLimit may gain constants in a feature release: keep an else. The ABI dump does not record the opt-in gate, so no check guards it.

Compatibility & versioning

      
  • webtools-feeds 1.0.0: new and not on Maven Central yet; it moved no version. Its javadoc jar holds the Dokka reference.
  • Checked: the ABI dump api/webtools-feeds.api, 321 lines with no Rome, JDOM, SAX or slf4j type, by apiCheck in check; verifyJavaFloor holds the module's jars and Rome's, JDOM's and rome-utils' classes to Java 11; the common code compiles for js.
  • Stable Core changes only in a major; an Experimental seam may change in a minor.
  • An entry's digest id hashes what the parser produced: a Rome upgrade, another parser or another maxIdChars can change it.

    
Thread safety

      
  • Every member of FeedFetcher may be called concurrently from any thread and coroutine; its closed flag is a completed Job, so close() runs once.
  • RomeFeedParser is immutable and thread-safe: every parse builds its own reader, input, builder and SAX parser. A FeedParser of your own must be thread-safe too.
  • Feed, FeedEntry, FeedEnclosure, FeedLimits, FeedValidators and FeedFetch are immutable; FeedInput copies its bytes in and out.
  • Confined: FeedFetcherConfig and the builders, each reachable only inside its lambda.

    
Resources to close

      
  • FeedFetcher is AutoCloseable: close() is idempotent, non-suspending, never throws and safe from any thread.
  • It closes the UrlFetcher only when FeedFetcher.untrusted built it, which closes its transport; a parse already running is not interrupted.
  • RomeFeedParser holds nothing to close.
  • JDOM's process-wide namespace cache never evicts: a parse adds at most maxNamespaceUris (64) new URIs to it.

  • Who consumes it: other repositories of this organization only (visibility internal · org).

    
Hardening and memory

      
  • A DOCTYPE, an encoding outside the set the parser reads, a prolog over 64 KiB and a prolog that decodes two ways are refused before any parser runs; external entities, DTDs and includes are never resolved.
  • Bounded in the same pass: depth 256, 100 attributes per element, 100,000 elements, 64 distinct namespace URIs; at most 1,000 entries; each value can only be tightened.
  • About 128 MB of heap headroom covers the default two concurrent parses of one fetcher; it grows with the sum of every fetcher's maxConcurrentParses.
  • The limits rest on sampled feeds, and a legitimate document beyond one fails; the scan's decoder rule was measured on JDK 23.0.2 only, and no JDK 11 runtime has run the parser.

    
Logging and secrets

      
  • One logger, com.spartanlabs.webtools.feeds.FeedFetcher: INFO on creation and close, one DEBUG line per fetch, a WARN for a refused document; the parser logs nothing of its own.
  • A URL is printed as scheme, host and port; never a header value, a body, document content or a validator, and toString() prints presence and counts.
  • The UrlFetcher it composes, and the transport under it, print a URL with its path: a secret carried in a feed URL's path appears in their lines.
