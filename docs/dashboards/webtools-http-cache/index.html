webtools-http-cache

The response cache of the suspend HTTP stack: it serves one decoded value per key to many concurrent callers from one load, for a bounded time, and never caches a failure. A consumer calls the ResponseCache port's getOrLoad(key, policy, maxAge, loader) under its eleven-point contract: a call joins the load in flight for an equal key, a Found lives for the policy's ttl and a Missing for its missTtl from the load's completion, a stored entry older than the call's maxAge is not served, and a caller's cancellation cancels only that caller. CaffeineResponseCache, the supplied default on the JVM, holds one shared future per key under a weight bound and runs each load in its own scope; ResponseCache.Disabled stores nothing and runs every loader on the caller's coroutine. The port, its values and Disabled are common code.

Lifecycles and rules

    
A cache's life, an entry's, and the rules the cache holds to.

    

      
A CaffeineResponseCache's life the supplied cache

        
  1. CaffeineResponseCache { maxWeight = 5_000 }: every property has a default (timeSource, maxWeight 1,000, loadDispatcher, maintenanceExecutor); it throws IllegalArgumentException for a maxWeight below 1
  2. getOrLoad(key, policy, maxAge, loader): a live entry within maxAge is served; a call while a load is in flight joins it; otherwise the call starts one, in the cache's own scope
  3. a load's end: a Found stored for ttl, a Missing for missTtl, each from the load's completion; a zero TTL or a value over maxWeight is delivered and not stored; a failure is never stored
  4. close(): idempotent, non-suspending, never throws; cancels the loads in flight, ends every waiting call with Closed("cache") without waiting for a loader to unwind, and drops every stored entry
  5. after it, getOrLoad returns Closed("cache") without running its loader; invalidate and invalidateAll are no-ops, stats keeps working

        
Three execution contexts: a caller only awaits, and its cancellation cancels only that caller; a loader runs in the cache's scope on loadDispatcher; Caffeine's maintenance runs on maintenanceExecutor. A loader must not wait for a load of its own key.

      
An entry's life CacheEntry

        
  1. claimed: one shared future per key, created by the call that starts the load
  2. settled once by the first of three completers: the load's body, close()'s sweep, or the job's completion handler; every load ends as a value, so Caffeine never sees an exceptional completion
  3. its lifetime decided once, when the load ends: ttl, missTtl or 0 for a failure, a zero TTL or a value over the bound
  4. expired by Caffeine, evicted by size, invalidated, or dropped by close(); a stale one is removed by identity when a call finds it past its maxAge

        
Its own counts: hits (joins included), misses, size evictions only, and failed loads, kept by the cache itself, with no recordStats() and no Caffeine Scheduler.

      
Rules the cache holds to

        
Failures are never stored. A loader's failure reaches every waiter as the same instance, and the next call loads anew.

        
The weight bound holds at every instant. A Found weighs what it reports, a Missing 1; one over maxWeight is delivered and never stored.

        
Nothing prints a secret. A CacheKey prints its parameter names only; a Found its weight; the log lines never a value, a parameter value or a message text, and nothing per hit or join.

        
Common code stays common. The port, its values, Disabled and the runner are compiled for js by the check module; only the Caffeine default is JVM code.

Guarantees

  

    
Failure model

      
  • getOrLoad returns a loader's failure inside the Result, the same instance for every waiter, and never stores it, so the next call loads anew; Closed("cache") after close().
  • A loader's Error is rethrown to every waiter as the same instance; a loader's own cancellation becomes Result.failure(IllegalStateException(…, cause)), never a CancellationException inside a Result.
  • Thrown, not returned: IllegalArgumentException for a negative maxAge or a maxWeight below 1; a caller's own cancellation, which cancels only that caller.
  • Retried inside: nothing; at most one reload per call.

    
Extension points

      
  • ResponseCache — implement Experimental behind @OptIn(ExperimentalForInheritanceWebToolsApi::class); calling and passing it are Stable Core
  • CaffeineResponseCache — final, built by its factory, usable without the opt-in; its builder sets timeSource, maxWeight, loadDispatcher and maintenanceExecutor Stable Core
  • ResponseCache.Disabled needs no opt-in Stable Core
  • Lookup — sealed, its closed pair the contract, so a when over it needs no else Stable Core

Compatibility & versioning

      
  • Ships in webtools-http 1.0.0: new, unreleased, not on Maven Central until the HTTP stack is complete.
  • Checked: the module's ABI dump api/webtools-http.api by apiCheck in check. The dump does not record sealed; a Level 1 test's when with no else holds Lookup's.
  • ResponseCache's implementation seam graduates to @SupportedExtension once a consumer has built against it, recorded in CHANGELOG.md.
  • Experimental seams may change in a minor release; Stable Core changes only in a major.

    
Thread safety

      
  • Every member of a ResponseCache may be called concurrently from any thread and any number of coroutines.
  • CacheKey, CachePolicy, Lookup and CacheStats are immutable; Disabled is stateless and shared.
  • stats() reads its four counts separately, not atomically.
  • Confined: a builder, reachable only inside its factory's lambda.

    
Resources to close

      
  • ResponseCache is AutoCloseable: close() is idempotent, non-suspending and never throws.
  • CaffeineResponseCache.close() cancels the loads in flight, ends every waiting call with Closed("cache") and drops every stored entry. Skipped, nothing of its own keeps the JVM alive: it owns no thread, timer or pool, and it never shuts down the maintenanceExecutor it was given, which must outlive the cache's last write.
  • ResponseCache.Disabled.close() does nothing.
