webtools-http-transport

The OkHttp transport of the suspend HTTP stack: OkHttpTransport, the supplied HttpTransport, delivers one request per hop to the network under an outbound-URL policy. A consumer builds it with the factory OkHttpTransport(userAgent, policy), which takes every number from the policy's settings, and calls execute(request) and close(). It refuses a request carrying a header it controls and one the policy refuses before any socket; follows redirects itself, judging each target by the policy and dropping sensitive headers once the origin changes; keeps one deadline across every hop; reads a capped decoded body where cancellation can reach it; never retries, with a guard that fails any second exchange of a hop; and maps every outcome to the failure model. Its client, guard, bridge and mapping are internal; it owns one daemon dispatcher.

Lifecycles and rules

    
A transport's life, one hop's, and the rules the transport holds to.

    

      
An OkHttpTransport's life one client per transport

        
  1. OkHttpTransport(userAgent, policy) validates both, then builds one client with its own dispatcher and connection pool; it throws IllegalArgumentException, leaving no thread behind, for a blank or non-printable userAgent or a maxResponseBytes above 2,147,483,639
  2. execute(request): the controlled headers, then the policy, both before any socket; then one Call per hop under one deadline
  3. a hop's response decides: Protocol outside 100..599, a followed redirect with no body read, else the response with its capped body
  4. close(): cancels every call in flight, each ending Closed("transport"); shuts the dispatcher down; evicts the idle connections
  5. after it, execute returns Closed("transport"); a second close() does nothing

        
Never a retry: OkHttp's retries, redirects, authentication, cookies and cache are off, and a network interceptor fails a second exchange of one hop as RetryRefused; a 407, 408, 421 or 503 is delivered once, as the response it is.

      
One hop one enqueued Call

        
  1. the hop's request from the Url's own text, the caller's headers, the factory's User-Agent, and Accept-Encoding: identity beside a Range
  2. its limit what is left of the one deadline; below a millisecond the hop ends in Timeout
  3. enqueued; the caller suspends, and its cancellation cancels the Call
  4. inside onResponse: the status restored, then the redirect decision, the headers and the body
  5. resumed exactly once with a value, never a throwable; the response closed

        
A received value is sanitised: a header name that is not a token is dropped, and CR, LF and NUL in a value become SP, as the port's contract says.

      
Rules the transport holds to

        
The policy before any socket. The request and every redirect target are judged by the outbound-URL policy's classifier; its resolver and socket guards ride on the client for an Untrusted policy.

        
Memory bounded by the cap. A declared length above maxResponseBytes fails at once with no read; otherwise the read asks for one byte more than the cap, so memory stays within the cap plus one okio segment.

        
Nothing prints a secret. No header value, body, query string or resolved address in a log line or a failure; a cause is kept only where its text holds no address. INFO once on creation and on close, DEBUG per call, hop and failure, WARN once for a policy refusal and a refused second exchange.

Guarantees

  

    
Failure model

      
  • execute returns Result: any status in 100..599 is a response, a 304 included; every failure is one TransportFailure leaf, first match wins: a policy refusal (RefusedByPolicy), a second exchange (RetryRefused), Closed, then DnsFailed, Timeout, TlsFailed, ConnectFailed, Protocol, Io, with BodyTooLarge and TooManyRedirects for its caps.
  • A request carrying one of the twelve controlled headers fails with InvalidRequest before anything is sent, though HttpRequest builds it.
  • Thrown, not returned: the factory's IllegalArgumentException; the caller's cancellation, which cancels the Call.
  • Retried inside: nothing.

    
Extension points

      
  • OkHttpTransport — final, built by the factory OkHttpTransport(userAgent, policy), usable without the opt-in Stable Core
  • Every number comes from the policy's TransportSettings: no builder and nothing to override Stable Core
  • To substitute the transport, implement the core's HttpTransport Experimental; the client, the guard, the bridge and the mapping are internal

Compatibility & versioning

      
  • Ships in webtools-http 1.0.0: new, unreleased, not on Maven Central until the HTTP stack is complete.
  • Checked: the module's ABI dump api/webtools-http.api by apiCheck, and the Java 11 floor by verifyJavaFloor, both in check.
  • Pinned to okhttp-jvm 5.5.0: the one-exchange guard and the status hiding are measured against that version.
  • Stable Core changes only in a major.

    
Thread safety

      
  • OkHttpTransport is safe to share: its only mutable state is its closed flag.
  • execute may be called concurrently and is main-safe: every blocking step runs on the transport's own daemon dispatcher, never on the caller's thread or dispatcher; maxConcurrentRequests and its per-host limit bound the calls.

    
Resources to close

      
  • close() cancels every call in flight, shuts its dispatcher down and evicts its idle connections, and is the supported stop; it is idempotent, non-suspending and never throws.
  • Skipped, nothing keeps the JVM alive: its threads are daemons, gone after 60 s idle, and a pooled connection goes after idleConnectionTtl.

    
On your classpath

      
  • com.squareup.okhttp3:okhttp-jvm:5.5.0 — runtime only, an implementation dependency of webtools-http; no OkHttp type is in the transport's public API. It lifts kotlin-stdlib to 2.2.21 or newer at runtime.
  • okhttp-tls 5.5.0 is the module's own jvmTest dependency and reaches no consumer.
  • Who consumes it: other repositories of this organization only (visibility internal · org).
