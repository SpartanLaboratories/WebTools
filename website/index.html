Internet I/O in single-concern artifacts.

A small Kotlin/JVM collection of internet I/O helpers, published as independent, single-concern artifacts: depend only on the one you need. Every fallible operation returns kotlin.Result rather than throwing, so callers decide how to recover.

What you get

Each artifact adds one concern, so you can take the parts you want and leave the rest.

A typed failure model

Every fallible operation returns kotlin.Result. HttpFailure carries TransportFailure (nothing usable came back), UpstreamFailure (RateLimited, UpstreamError), BudgetExhausted, DecodeFailure and Closed.

One fixed call path

UpstreamClient checks each call against the outbound-URL policy, then the response cache, then the call budget, then the transport. A hit costs nothing, and N concurrent callers of one key cost one permit and one request.

Outbound-URL policies

Trusted for an upstream you chose, Untrusted for a URL a third party supplied: lenient host forms, reserved names, denied addresses, other ports and sensitive headers are refused.

A response cache

CaffeineResponseCache: one load per key at a time, per-entry lifetimes, a weight bound, a per-call maxAge, failures never stored. ResponseCache.Disabled stores and shares nothing.

A call budget

WindowedCallBudget: epoch-aligned rate windows with a boundary guard, per-lane floors, first-come-first-served waits that fail fast or are refunded and re-planned, pauses from Retry-After, and a hard window that survives a restart through a BudgetStore.

Hardened feeds

RSS 0.90 to 2.0, RSS 1.0 and Atom 0.3 and 1.0 behind FeedParser. RomeFeedParser refuses a DOCTYPE before any parser runs and bounds depth, attributes, elements and namespaces; FeedFetcher does a stateless conditional GET and returns a 304 as a value.

UDP with a reliable channel

MultiConnectionUDPServer multiplexes every client over one socket after a NAT-traversal handshake. UdpChannel gives each connection an UNRELIABLE or a RELIABLE_ORDERED delivery mode.

Test support

webtools-http's test fixtures (Gradle testFixtures(...)): FakeHttpTransport, VirtualClock, .http fixtures, a recorder, LoopbackFetchers and FakeBudgetStore.

Architecture

Five artifacts, one concern each. Only webtools-feeds depends on another.

Responsibility of each artifact
ArtifactResponsibility
webtools-httpThe suspend HTTP client stack: request and response types, a typed failure model, the transport, cache, budget and outbound-URL policy ports with their supplied implementations, and the UpstreamClient and UrlFetcher facades.
webtools-feedsRSS and Atom behind a hardened parser port, the feed model with a frozen entry id, and FeedFetcher, a stateless conditional GET over UrlFetcher. Exposes webtools-http as an api dependency.
webtools-udpA multi-client UDP connection layer: one common port, a NAT-traversal handshake, framed datagrams, keepalive, a link-quality probe and a reliable-ordered channel. Depends on slf4j-api only.
webtools-scrapingConnector: open a URL and read it line by line, plus one-shot get, skrape and image download helpers. Archived.
webtools-browserWebViewer: headless-browser screenshots through Selenium Manager. Archived.

Install

Published to Maven Central. Requires JDK 11 or newer; built with Kotlin 2.2.

Maven and the -jvm artifacts

webtools-http and webtools-feeds are Kotlin Multiplatform modules that publish webtools-http and webtools-http-jvm (likewise for feeds). A Gradle build resolves the right one itself; a Maven build depends on the -jvm artifact. testFixtures(...) is Gradle-only.

Kotlin standard library

webtools-http's okhttp-jvm 5.5.0 dependency requires kotlin-stdlib 2.2.21, so a consumer's Kotlin standard library resolves to 2.2.21 or newer.

The archived modules

webtools-scraping and webtools-browser are archived. Their install lines and the Java 11 floor notes for their older releases are in the README.
